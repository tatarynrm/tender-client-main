# CLAUDE.md

Фронт ICT Tender Platform — логістична тендерна платформа: перевізники подають ставки, менеджери ICT ведуть тендери й вантажі, адміністратори керують системою. **Уся текстівка інтерфейсу — українською.**

Next.js 15 App Router + React 19, порт 3000. Бекенд (NestJS) живе в окремому репозиторії `tatarynrm/tender-server` і деплоїться нарізно.

## Швидка перевірка

```bash
npx tsc --noEmit     # головна перевірка: типи
npm run build        # повна збірка (довша)
```

Тестів немає — перевірка типів і є перевіркою.

## Три робочі простори

`app/` містить **тільки маршрути**: серверний компонент + `metadata` + рендер одного компонента з `features/`. Уся логіка — у `features/`.

| Простір | Аудиторія | Гейт |
|---|---|---|
| `app/dashboard/` | перевізники | `!role.is_ict && !role.is_admin` |
| `app/log/` | менеджери ICT | `role.is_ict` |
| `app/admin/` | адміністратори | `role.is_admin` |

Доступ перевіряється **в `layout.tsx` кожного простору** через `await getProfile()` з редіректом. [middleware.ts](src/middleware.ts) — порожній passthrough; перевірки туди не додавати, канонічне місце — layout.

[getProfile()](src/shared/server/getProfile.ts) читає куку `centrifuge` і сам ходить на `SERVER_URL/auth/me`. Дві різні змінні оточення: `SERVER_URL` — для серверних компонентів, `NEXT_PUBLIC_SERVER_URL` — для браузера. Обидві вказують на той самий бекенд.

## Запити до бекенда

Єдиний axios-інстанс [shared/api/instance.api.ts](src/shared/api/instance.api.ts) (`baseURL` + `withCredentials`). Авторизація тримається виключно на кукі — токенів немає, тому **`fetch` або новий axios-інстанс до Nest = запит без куки = 401**.

Виняток — власні route handlers Next (`app/api/**/route.ts`). Вони на тому ж origin, туди ходять звичайним `fetch` з відносним шляхом. Такий роут **не проходить через AuthGuard Nest** і гейтиться вручну через [requireAdmin()](src/shared/server/requireAdmin.ts).

Бекенд віддає обгортку `{ status, content, props?, add_data? }`: списки зазвичай повертають цілою обгорткою (у `props` пагінація), одиничний запис — розпакованим `content`.

## Стан

TanStack Query для серверних даних, zustand — лише для UI-стану (модалки, нотифікації адміна). Socket-події зводяться до `queryClient.invalidateQueries`, а не до ручного мутування кешу.

## Дані приходять зі збережених процедур

Бізнес-логіка живе в Postgres, а не в TypeScript. Бекенд — тонка обгортка над `callProcedure`. **Схему й процедури БД не змінюємо** — їх веде окремий розробник.

Практичний наслідок для фронта: якщо для екрана потрібні дані, яких жоден наявний ендпоінт не віддає, **не вигадуй ні SQL, ні фейкові дані**. Опиши, якого саме набору полів бракує, — потрібну процедуру замовлять окремо.

## Дрібниці, на яких легко спіткнутися

- Аліас `@/` → `client-ai/src/`.
- Кириличні JSON і TS-файли — UTF-8 без BOM.
- Значні зміни фіксуються записом у `src/shared/data/changelog.json`; **категорія визначає, хто його прочитає**: перевізник бачить `carrier` + `all`, тому в `all` не можна писати нічого про внутрішні процеси ICT.
